# Impeccable — GLC

## Design Context

### Users

- **Primary:** Consultants, которые ведут B2B-аудиты для SMB: нужны предсказуемость, скорость и передаваемые клиенту артефакты.
- **Secondary:** Владельцы и операционные команды; клиенты в портале — контекст «важное решение», не развлечение.
- **Job to be done:** Одна сохраняемая картина бизнеса → приоритеты → дорожная карта без хаоса и без «ещё одного чата».

### Brand Personality

**Три слова:** уверенный, структурный, честный по scope.

- Тон: спокойная экспертиза, без хайпа «магии AI»; акцент на контексте, доказательности и следующих шагах.
- Эмоции: **уверенность** и **контроль**, не тревога и не игривость.

### Aesthetic Direction

- **База:** текущий GLC — продуктовый chrome (`AppShell`), маркетинговый слой с токенами CSS (`--glc-*`, `--text-*`, `--bg-*`), иконки Phosphor, без emoji в коде.
- **Тема:** маркетинг и публичные экраны — тёмная/нейтральная «product» эстетика уже заложена; не уходить в «ещё один cyan-on-dark SaaS» без причины.
- **Анти-референсы:** шаблонные карточки «иконка + заголовок + текст» рядами; градиентный текст как единственный акцент; декоративные полоски `border-left` на карточках как замена иерархии.

### Design Principles

1. **Иерархия типографики** — меньше размеров, больше контраста; длинные блоки с `max-width` для читаемости.
2. **Ритм отступов** — разный вертикальный ритм (сжатые группы / широкие разделители), не одинаковый padding везде.
3. **Движение** — умеренно, с уважением к `prefers-reduced-motion` (как уже в `MarketingSection` / hero).
4. **Доступность** — семантика, подписи контролов, не серый текст на цветном фоне без проверки контраста.
5. **Согласованность с кодовой базой** — новые визуальные решения через существующие токены и паттерны; не плодить параллельные «дизайн-системы».

### Notes for /impeccable craft

- Перед сменой шрифтов или палитры сверяться с `src/app/config` и глобальными стилями; маркетинг уже использует `font-display` и бренд-градиенты.
- **Gradient text** (`background-clip: text`) — абсолютный бан. Класс `.glc-gradient-text-flow` удалён из `src/styles/features.css`; landing-hero (`SnapshotLandingHeroForm`) теперь использует solid `text-[var(--glc-blue)]` с font-weight для иерархии. Не возвращать gradient-text — fail contrast в части градиента и ломается под forced-colors.
- **Border-left ≥ 2px как декоративный strip** — абсолютный бан. Удалены: `.ds-bank-classic-section-header-tint` (2px → теперь только background tint + padding-left), `.ds-rec-card-accent-border` (3px → удалён, quick-win обозначается через `QuickWinTag` badge внутри карточки). Не возвращать боковые цветные стрипы — заменять иерархию на background tint, badge или icon-led header.
- **Cascade `<details>` 5+ уровней** — анти-паттерн «AI dashboard». В Strategy Lab консолидировано на двух уровнях: страница — единственный `<Accordion>` `Reference: peer benchmarks and constraint overrides` с always-visible preview-line (benchmarks count + constraint state) в `StrategyLabPage.tsx`; панель — единственный `<Accordion>` `Advanced settings` (Stage-2 intent + snapshot history + commercial offers) с always-visible preview-line + flat `<section>` `Plan diagnostics` для governance / revisions / pack inspection в `StrategyLabOrchestrationPanel.tsx`. Native `<details>` в `src/app/pages/strategy-lab/*.tsx` запрещены — используем `<Accordion>` primitive для consistency a11y / preview-summary contract (тест `StrategyLabPage.steps-strip.test.tsx` проверяет это инвариантно). Перед добавлением нового скрытого блока спросить: должен ли пользователь это видеть сразу? Если да — flat секция с `<h3>`.
- **Steps strip как точка входа** — на сложных multi-step экранах (Strategy Lab) использовать 3-шаговый `<nav><ol>` с `aria-current="step"` на текущем шаге, derived из реальных бэкенд-сигналов (наличие `effective_constraints`, `manifest_snapshot_id`, `orchestration_pack_version`). Копия шага 2 центрируется на инициативах/конфиге плана («Initiatives»); шаг 3 — «Pack & roadmap». См. `STRATEGY_LAB_COPY.stepsStrip` SSOT и `StrategyLabPage.tsx`; переключение на consultant roadmap через `WorkbenchSegmentedNav` над steps strip.
- **CTA hierarchy в формах с saving + executing** — primary action (`Build pack`) идёт `variant="default" size="lg"` с иконкой; secondary (`Save snapshot`) — `variant="outline"`. Через `aria-describedby` связывать disabled-кнопку с текстовым hint (`buildPackNeedsManifestSync`), а не показывать tooltip.
- **Inline-confirm вместо modal AlertDialog** для in-context destructive/commercial actions: `<div role="group" aria-labelledby aria-describedby>` с `Confirm` + `Cancel`, без overlay. См. commercial accept в `StrategyLabOrchestrationPanel.tsx`. Modal `AlertDialog` оставлять только для глобально-блокирующих действий (logout, delete account). `window.confirm()` запрещён — не локализуется, не тестируется, ломает focus order (WCAG 2.4.3 / 4.1.2).
- **Single orchestrator tab-bar поверх Steps strip** — параллельные tab-наборы запрещены (анти-паттерн "tab overload"; пользователь не понимает что выбрать первым). На multi-view экранах допустим один primary tab-bar; в Strategy Lab это orchestrator tabs `now / next / dependencies / risks` в `StrategyLabPage.tsx`, ориентир по статусу даёт Steps strip над ним. Полный ARIA-tabs pattern обязателен: `role="tablist"` + `role="tab"` + `aria-selected` + `aria-controls` + roving `tabIndex` + `role="tabpanel"` + `aria-labelledby` (тест `StrategyLabPage.orchestrator-tabs-a11y.test.tsx` фиксирует контракт).
- **Workbench segmented routing (`Orchestration | Roadmap`)** не считается вторым tab-баром: это переключение маршрутов consultant surfaces (`/strategy/:id` vs `/roadmap/:id`), не вкладки внутри одного SPA-view. Компонент `StrategyLabWorkbenchSegmentedNav` дублируется на страницах Strategy Lab и Roadmap schedule под флагом `orchestrationRoadmapUiEnabled` для зеркальной навигации.
